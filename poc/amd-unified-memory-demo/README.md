# `amd-unified-memory-demo` — the APU "no PCIe copy" zero-copy win, measured

Strix Halo's real hardware advantage is not raw iGPU FLOP/s — it is the **94 GB
unified LPDDR5X pool** shared by the CPU and the Radeon 8060S iGPU. This demo
makes the consequence **measurable**: a HIP microbench that times the three
allocation strategies head-to-head on `gfx1151`, so you can see the "zero-copy /
no-PCIe-copy" advantage in GB/s instead of taking it on faith.

> **Honesty rule.** This is a plain memory-bandwidth micro-demo (SAXPY,
> memory-bound). It backs course module **M2 — Unified memory** by quantifying
> the zero-copy advantage; it is **not** a ZK proof and makes no proving claim.
> `rocm-smi` power on this APU is whole-SoC package power, not an isolated iGPU
> rail. iGPU/NPU accelerate AI models; the iGPU's OpenCL path accelerates SNARK
> primitives (size-gated); the RISC0 STARK is CPU-only on AMD.

## The three allocations (and what each one teaches)

| alloc | what it is | the discrete-GPU model | on this APU |
|---|---|---|---|
| `hipMalloc` | device-only buffer | needs an **explicit `hipMemcpy` H2D/D2H** over **PCIe** to move data | the "copy" is intra-LPDDR5X, but you still pay a staging copy |
| `hipHostMalloc` | pinned host buffer, GPU-addressable | **zero-copy**, but every access crosses **PCIe** (slow on discrete) | zero-copy with **no staging copy** — same LPDDR5X, so ~device speed |
| `hipMallocManaged` | unified managed memory | pages **migrate on demand** (HMM/XNACK), first touch is costly | cold first-touch migrates; warm runs hit device-resident speed |

The kernel is a memory-bound SAXPY (`y = a*x + y`, 3 floats of traffic per
element), so its headline number is **GB/s** — exactly the axis the unified
pool moves.

## Run it

```bash
make demo-uma               # from repo root: build + solo-guarded run -> uma-bandwidth.{csv,md}
# or directly:
cd poc/amd-unified-memory-demo
bash scripts/run-all.sh
UMA_N=$((1<<25)) REPS=100 bash scripts/run-all.sh   # bigger buffers / more reps
```

`run-all.sh` sources the repo's [`solo-guard.sh`](../risc0-cartesi-step-demo/scripts/solo-guard.sh)
**before** timing: it refuses (exit 42) to record under iGPU/CPU contention and
stamps every CSV row with `solo` + `loadavg`. Set `ZKP_SOLO_OVERRIDE=1` to force
a recording (then stamped `solo=false`, so contamination stays visible).

## Committed measurement (real, solo)

The committed `artefacts/uma-bandwidth.csv` is a real run on the box below, taken
in a **`solo=true`** window (the iGPU is frequently contended by a third-party
`train_language.py` job; this row was recorded while it was idle):

- **Hardware:** AMD Ryzen AI MAX+ PRO 395 / Radeon 8060S (`gfx1151`), ROCm 7.2.3
- **Buffer:** 64 MiB/array (`UMA_N=2^24`), REPS=50

| alloc_kind | op | GB/s | note |
|---|---|---:|---|
| `hipMalloc` | `memcpy_h2d` | ~75 | explicit staging copy in |
| `hipMalloc` | `kernel_saxpy` | ~218 | device-resident (best case) |
| `hipMalloc` | `memcpy_d2h` | ~63 | explicit staging copy out |
| `hipHostMalloc` | `kernel_saxpy` | ~209 | **zero-copy, no staging** |
| `hipMallocManaged` | `kernel_saxpy_cold` | ~124 | first-touch page migration |
| `hipMallocManaged` | `kernel_saxpy_warm` | ~213 | pages resident |

**The teaching result:** zero-copy host-pinned memory reaches **~209 GB/s — within
a few percent of the ~218 GB/s device-resident kernel** — because there is **no
PCIe**: the kernel reads the host buffer directly from the same LPDDR5X. On a
discrete card that zero-copy path would crawl across PCIe. Managed memory pays a
one-time **first-touch migration** (cold ~124 GB/s) that amortises to
device-resident speed once the pages are resident (warm ~213 GB/s). The explicit
`hipMalloc` model still pays a staging copy (~75/63 GB/s H2D/D2H) just to get the
data device-resident — the tax the unified-memory paths skip entirely.

(Numbers are a single real run; re-running gives slightly different values from
iGPU clock ramp + shared-SoC contention. That variance is expected.)
